# v0.2 Design: Market Data + Literature-Derived Metrics + Rule Engine

Status: approved
Date: 2026-09-13
Builds on: [v0.1 Ledger + Deterministic Analytics](2026-08-18-v0.1-ledger-and-math-design.md)

## Purpose

v0.1 proved the ledger and the core math (XIRR, allocation drift, FIFO tax lots)
are correct. v0.2 layers retail-investor investment literature on top of that
foundation — as deterministic, cited, unit-tested computation.

The organizing claim of this spec: **almost everything valuable in the retail
investment literature is deterministic.** Cost drag, behavior gap, concentration,
rebalancing bands, rolling-return consistency — these are formulas and thresholds
from named sources, not judgment calls. They belong in Python with citations, not
in a model. What genuinely needs an LLM is *explanation and prioritization of
findings that already exist*, and that is deferred to v0.3.

v0.2 therefore contains **no LLM call of any kind**, preserving v0.1's
non-negotiable #3 unchanged.

## Non-negotiables (carried forward, with one amendment)

1. **Fully local for portfolio data.** Holdings, amounts, folio numbers, and PAN
   never leave the machine. **Amended in v0.2:** outbound fetches of *public
   market reference data* are permitted, under a strict rule stated below.
2. **No execution.** No order-placement code path. Unchanged.
3. **Deterministic math is never delegated to an LLM.** v0.2 has no LLM calls.
   Unchanged.
4. **Redaction gate for any future hosted-model call.** Still not applicable
   (no LLM calls exist in v0.2), but v0.2 shapes the `Finding` type so the gate
   has almost nothing to strip. See Rule Engine.

### The outbound-data rule

`marketdata` may make outbound HTTP requests, subject to one invariant:

> **No request may carry a portfolio-derived parameter.**

Client functions accept dates only — never an ISIN, scheme name, folio, or
amount. AMFI publishes whole-universe files, so the natural access pattern is
already "download everything, filter locally." Scoping to your holdings happens
after download, on-machine.

This is enforced by function signature and verified by test: a unit test asserts
that every outbound URL the client constructs contains no ledger-derived value.
Downloading the same public file every Indian investor downloads reveals nothing
about the portfolio; querying it by your ISINs would.

## Scope

In scope for v0.2:
- A `marketdata` layer: AMFI NAV universe + NAV history, parsed, incrementally
  cached in SQLite.
- Five deterministic literature-derived metric modules (behavior gap, cost drag,
  diversification, consistency, rebalancing).
- A rule engine emitting typed, cited, PII-free `Finding` objects.
- A five-dimension portfolio health score, persisted per run for tracking.
- Backfill of v0.1's `schemes.asset_class` from AMFI's SEBI categorization.

Out of scope for v0.2 (explicitly deferred):
- **All LLM work → v0.3**: explanation, prioritization, narrative synthesis,
  reading scheme documents (SIDs/factsheets), and the redaction gate
  implementation.
- **Holdings-level fund overlap** — data-blocked, see Deferred Metrics.
- **Index-benchmark comparison** — data-blocked, see Deferred Metrics.
- MVO/covariance optimizer, UI, broker API integration, tax liability amounts.

## Data Source Reality

Endpoint availability was verified on 2026-09-13. This is recorded because two
otherwise-obvious metric families turned out to be data-blocked, and the spec's
shape follows from that.

| Source | Status | Notes |
|---|---|---|
| AMFI NAV universe | Available | `portal.amfiindia.com/spages/NAVAll.txt`, ~18k lines / 1.5MB |
| AMFI NAV history | Available | date-range download, whole universe, ~3.6MB per 5 days |
| SEBI scheme category | Available | embedded as headers in the NAV files |
| Direct/Regular plan | Partial | explicit `Plan` column, but empty for 40% of rows — see Plan Coverage |
| Scheme TER | **Not available** | no machine-readable feed; every plausible AMFI endpoint 404s |
| Scheme monthly holdings | **Not available** | per-AMC disclosures only, no aggregator |
| Index/benchmark series | **Not available** | NSE refused programmatic access |

Note: `www.amfiindia.com/spages/NAVAll.txt` 301-redirects to the `portal.`
host. Use `portal.amfiindia.com` directly.

### Consequences

- **TER unavailable → cost drag is measured empirically instead.** Rather than
  TER arithmetic, v0.2 compares the Direct and Regular NAV series of the same
  scheme. The realized spread *is* the drag, and it is a better number than
  stated TER because it captures trail commission as actually charged.
- **Holdings unavailable → overlap is approximated by SEBI-category
  duplication.** This catches the dominant real-world failure mode (owning four
  funds in one category) without 40 fragile per-AMC scrapers.
- **Benchmark unavailable → comparison is peer-relative.** AMFI groups every
  scheme by SEBI category, so ranking against actual category peers is
  available and is arguably more useful than index comparison for fund
  selection.

### Deferred metrics

Holdings-level overlap % and index-benchmark tracking error are **not built** in
v0.2. Their absence is a data constraint, not an oversight. If an aggregated
source appears, both slot in behind the existing metric interface without
disturbing the rule engine. No scraping is attempted.

Enforced rules:
- `analytics` reads `marketdata`'s **cache tables**, never its HTTP client.
  Analytics code performs no I/O beyond DB reads and stays unit-testable with
  synthetic data — the v0.1 property, preserved.
- Nothing outside `ingest` imports `ingest`. Unchanged from v0.1.
- `rules` depends on `analytics` and never recomputes a metric itself.
- v0.3's LLM layer will sit above `rules` and consume `Finding` objects only.

## Market Data Layer

### File format

Both AMFI endpoints are semicolon-delimited with interleaved unfielded lines:

```
Scheme Code;ISIN Div Payout/ ISIN Growth;ISIN Div Reinvestment;Scheme Name;Plan;Option;Net Asset Value;Date

Open Ended Schemes(Debt Scheme - Gilt Fund)

Axis Mutual Fund

135762;INF846K01WO1;-;Axis Children's Fund;Direct Plan;Growth Option;29.9628;11-Sep-2026
```

Two kinds of non-data lines appear: SEBI category headers and bare AMC
names. Headers take three forms — `Open Ended Schemes(...)`,
`Close Ended Schemes(...)`, and `Interval Fund...` — and the scheme
structure they imply is retained, not just the category text, because
close-ended schemes are excluded from several metrics. The parser is a
state machine carrying the most recent category and AMC down onto each following
data row. The history endpoint has the same shape with an extra leading
`NAV Name` column, so the parser is parameterized by column layout rather than
duplicated.

Parsing notes: `-` denotes a missing ISIN; dates are `DD-Mon-YYYY` and are
normalized to ISO `YYYY-MM-DD` on write; a row whose NAV field is non-numeric
(some schemes report `N.A.`) is skipped and counted, not fatal.

### Plan coverage (measured 2026-09-13)

The `Plan` column is populated for only 60% of rows. Measured against the full
universe of 14,361 data rows:

| Segment | Rows | Plan present |
|---|---|---|
| Open-ended, non-ETF | 9,248 | 8,282 (89.6%) |
| Close-ended, non-ETF | 4,752 | 228 (4.8%) |
| ETF (open-ended) | 361 | 96 (26.6%) |

The plan is **not** recoverable from the scheme name: of 5,755 rows with an
empty `Plan`, only 8 mention Direct or Regular in the name. No fallback parse
is worth writing.

The missing values have three distinct causes, and they must not be collapsed
into one bucket:

- **Close-ended schemes (4,524 rows).** Mostly FMPs and capital-protection
  funds. The Direct/Regular distinction is largely inapplicable and these are
  not retail-purchasable on an ongoing basis. Cost drag treats them as
  **out of scope**.
- **ETFs (265 rows).** No plan distinction exists by construction — there is a
  single listed unit. Cost drag reports **not applicable**.
- **Open-ended non-ETF with no plan (966 rows, 10.4% of the addressable
  universe).** A genuine data gap. Cost drag reports **unknown**.

`md_schemes.plan` therefore uses four values rather than three:
`DIRECT`, `REGULAR`, `NOT_APPLICABLE` (ETF or close-ended), and `UNKNOWN`
(open-ended, plan genuinely absent). The distinction is what lets the metric
report honestly instead of silently narrowing.

### Schema (additive migration)

```sql
-- Scheme master, refreshed from the NAV universe file.
CREATE TABLE md_schemes (
    amfi_code       TEXT PRIMARY KEY,
    isin_growth     TEXT,
    isin_reinvest   TEXT,
    scheme_name     TEXT NOT NULL,
    amc             TEXT,
    sebi_category   TEXT,                  -- e.g. "Debt Scheme - Gilt Fund"
    plan            TEXT NOT NULL DEFAULT 'UNKNOWN'
                        CHECK (plan IN ('DIRECT','REGULAR','NOT_APPLICABLE','UNKNOWN')),
    scheme_structure TEXT NOT NULL DEFAULT 'OPEN'
                        CHECK (scheme_structure IN ('OPEN','CLOSED','INTERVAL')),
    is_etf          INTEGER NOT NULL DEFAULT 0,
    option          TEXT,                  -- Growth / IDCW
    asset_class     TEXT NOT NULL DEFAULT 'UNCLASSIFIED'
                        CHECK (asset_class IN ('EQUITY','DEBT','HYBRID','GOLD','CASH','UNCLASSIFIED')),
    last_seen       TEXT NOT NULL
);
CREATE INDEX idx_md_schemes_isin ON md_schemes(isin_growth);
CREATE INDEX idx_md_schemes_category ON md_schemes(sebi_category);

-- NAV time series. Filtered on write to ISINs present in the ledger,
-- so DB size is proportional to the portfolio, not the fund universe.
CREATE TABLE md_nav (
    amfi_code   TEXT NOT NULL,
    nav_date    TEXT NOT NULL,             -- ISO 8601
    nav         REAL NOT NULL,
    PRIMARY KEY (amfi_code, nav_date)
);

-- Which date ranges are already cached; makes backfill incremental.
CREATE TABLE md_fetch_log (
    fetch_id        INTEGER PRIMARY KEY,
    endpoint        TEXT NOT NULL,
    range_start     TEXT,
    range_end       TEXT,
    fetched_at      TEXT NOT NULL DEFAULT (datetime('now')),
    rows_ingested   INTEGER NOT NULL DEFAULT 0,
    rows_skipped    INTEGER NOT NULL DEFAULT 0
);

-- SEBI category → v0.1 asset_class mapping. Static, seeded, user-editable.
CREATE TABLE md_category_asset_class (
    sebi_category   TEXT PRIMARY KEY,
    asset_class     TEXT NOT NULL
                        CHECK (asset_class IN ('EQUITY','DEBT','HYBRID','GOLD','CASH'))
);

-- Health score history, one row per dimension per run.
CREATE TABLE health_scores (
    score_id    INTEGER PRIMARY KEY,
    computed_at TEXT NOT NULL DEFAULT (datetime('now')),
    dimension   TEXT NOT NULL CHECK (dimension IN
                    ('COST','DIVERSIFICATION','BEHAVIOR','ALLOCATION','TAX_EFFICIENCY')),
    score       REAL CHECK (score IS NULL OR (score >= 0 AND score <= 100)),
                                -- NULL = unmeasured (no data), distinct from 0
    finding_count INTEGER NOT NULL DEFAULT 0
);
```

### Incremental backfill

1. Determine the needed window: earliest ledger transaction date → today.
2. Subtract date ranges already recorded in `md_fetch_log`.
3. Fetch only the gaps, in chunked date ranges.
4. Parse, filter to ledger ISINs, upsert into `md_nav`, log the range.

Downloads remain whole-universe (the privacy invariant); filtering is local and
post-download. Subsequent runs fetch only new dates.

### asset_class backfill

v0.1 defaults `schemes.asset_class` to `UNCLASSIFIED` and its spec anticipated a
separate classification step. `md_category_asset_class` supplies it: join ledger
schemes to `md_schemes` by ISIN, map SEBI category → asset class, and update.
Anything unmatched stays `UNCLASSIFIED` and is surfaced by a rule, never
silently assumed. This materially improves v0.1's allocation drift tool.

### Degradation

Every metric degrades explicitly. If the cache lacks required data, the metric
returns `unavailable(reason)`, and dependent rules emit **no finding** rather
than a false clean. Silence caused by missing data is itself reported.

## Metrics

Each module is a pure function over ledger rows plus cached NAV, returning a
value or an explicit `unavailable(reason)`. Each reuses v0.1 math rather than
reimplementing it.

### `behavior_gap.py`
*Source: Morningstar,* Mind the Gap; *Dalbar QAIB.*

Compares your money-weighted return (v0.1 `xirr.py`) against the fund's own
time-weighted return over the same window, computed from `md_nav`. The
difference is the cost of timing. Computed per scheme and portfolio-wide.
Requires ≥2 cashflows and NAV coverage spanning them; otherwise unavailable.

### `cost_drag.py`
*Source: Bogle, cost-matters hypothesis; SEBI direct-plan regulation.*

For each Regular-plan holding, locate its Direct sibling (same AMC + scheme name
+ option, differing only in `plan`) and compare CAGR of the two NAV series over
your actual holding period. The spread is realized drag, including trail
commission. Projected forward over a user-specified horizon to show compounded
cost. An optional user-supplied TER field enables absolute cost reporting;
nothing depends on it.

**Coverage is reported, never implied.** Because `Plan` is absent for a
material share of the universe (see Plan Coverage), every cost-drag
result carries an explicit breakdown of the holdings it covered and the
ones it could not, each with a reason: `NOT_APPLICABLE` (ETF or
close-ended), `UNKNOWN` (plan absent from source data), or
`NO_SIBLING` (Regular plan whose Direct counterpart is not in the
universe). A portfolio-level drag figure is never presented without the
share of portfolio value it was computed over.

### `diversification.py`
*Source: SEBI scheme categorization framework; Herfindahl concentration.*

Counts schemes per SEBI category (four flexi-cap funds is the classic error),
computes effective number of holdings as `1 / Σ wᵢ²` against nominal count, and
flags divergence between them. Holdings-level overlap deferred.

### `consistency.py`
*Source: rolling-return methodology; SEBI category peer grouping.*

Distribution of rolling N-year returns rather than point-to-point (the error the
literature repeatedly flags), plus percentile rank against SEBI-category peers
from `md_nav`. Index-benchmark comparison deferred.

### `rebalancing.py`
*Source: Daryanani 5/25 rule; target-date glidepath literature.*

Threshold-band signals — rebalance when a class drifts 5 absolute points or 25%
relative, whichever binds first — plus age/horizon glidepath targets. Proposed
trades are run through v0.1's FIFO lot matcher to report which disposals would
be STCG vs. LTCG, making the recommendation tax-aware.

## Rule Engine

### The Finding contract

```python
class Severity(Enum):
    INFO = "INFO"; LOW = "LOW"; MEDIUM = "MEDIUM"; HIGH = "HIGH"

@dataclass(frozen=True)
class Subject:
    kind: str                       # "SCHEME" | "SECURITY" | "ASSET_CLASS" | "PORTFOLIO"
    ref: str                        # scheme name or ISIN — never a folio number
    weight: float | None = None     # portfolio share as a ratio, never an amount

@dataclass(frozen=True)
class Finding:
    rule_id: str                    # "cost.regular_plan_drag"
    severity: Severity
    title: str                      # short, factual, no advice language
    subjects: list[Subject]
    metrics: dict[str, float]       # every number behind the finding
    citation: CitationRef
    computed_at: str
```

Three properties, each load-bearing:

- **Self-contained.** Every number behind the finding is in `metrics`, so v0.3
  explains rather than recalculates. This is what keeps non-negotiable #3 intact
  once an LLM enters the picture.
- **Cited.** Every rule traces to a named source and the specific claim relied
  on. This is what makes v0.3's explanatory tier honest rather than an LLM
  generating plausible-sounding rationale.
- **PII-free by construction.** `Subject` carries scheme identity and ratios,
  never folio numbers, PAN, or absolute rupee amounts. The v0.3 redaction gate
  will therefore have almost nothing to strip — the boundary is designed clean,
  not filtered clean.

### Rules

One module per family under `rules/families/`, registered declaratively. Each
rule is `(context) -> list[Finding]`, where context bundles ledger rows and
computed metrics. A rule lacking data emits nothing and records why.

| Rule id | Family | Source |
|---|---|---|
| `cost.regular_plan_drag` | cost | Bogle; SEBI direct-plan regulation |
| `cost.coverage_incomplete` | cost | data-quality guard; fires when cost drag covers <90% of portfolio value |
| `tax.idcw_inefficiency` | tax | IDCW taxed at slab rate vs. Growth option |
| `tax.rebalance_stcg_exposure` | tax | v0.1 FIFO lots; STCG/LTCG holding-period thresholds |
| `behavior.timing_gap` | behavior | Morningstar, *Mind the Gap* |
| `diversification.category_duplication` | diversification | SEBI categorization |
| `diversification.low_effective_holdings` | diversification | Herfindahl |
| `consistency.peer_underperformance` | consistency | rolling-return methodology |
| `allocation.band_breach` | allocation | Daryanani 5/25 |
| `allocation.unclassified_holdings` | allocation | data-quality guard |

### Citations

A static registry mapping citation keys to source metadata: author/organization,
work, year, and the specific claim relied upon. Bogle for cost, Morningstar for
behavior, Daryanani for bands, SEBI circulars for categorization and taxation.

### Health score

Five dimensions — cost, diversification, behavior, allocation fit, tax
efficiency — each scored 0–100 from that dimension's findings weighted by
severity, and persisted to `health_scores` per run so movement is trackable
across statements.

Each rule family maps to exactly one dimension: `cost`→COST,
`diversification`→DIVERSIFICATION, `behavior`→BEHAVIOR,
`allocation`→ALLOCATION, `tax`→TAX_EFFICIENCY. A dimension with no
findings and no available data scores as `null`, not 100 — an
unmeasured dimension must never read as a clean one.

Weights live in a config file, not in code. The aggregate score is an opinion,
and it should be visibly tunable rather than presenting itself as objective.

## Testing Strategy

- **No network in the test suite.** Recorded AMFI fixture files (a trimmed
  NAVAll sample and a history sample) drive all `marketdata` tests, including
  the category/AMC state machine, `N.A.` NAV rows, and missing-ISIN `-` values.
- **Privacy invariant tests.** One test asserts every URL `amfi_client`
  constructs contains no ledger-derived value. One property test per rule family
  asserts no emitted `Finding` carries a folio number, PAN, or absolute rupee
  amount.
- **Coverage-reporting tests.** A fixture containing an ETF, a close-ended
  scheme, an open-ended scheme with an empty `Plan`, and a Regular scheme
  with no Direct sibling must produce a cost-drag result whose covered
  plus uncovered value equals total portfolio value, with each exclusion
  carrying its correct reason code.
- **Hand-computed metric expectations.** Each metric module is verified against
  manually traced examples, in v0.1's style.
- **Degradation tests.** With an empty or partial cache, each metric returns
  `unavailable` with a reason and its dependent rules emit zero findings — never
  a false clean.
- **Incremental backfill test.** Two consecutive cache runs over the same window
  must produce no additional fetches and no duplicate `md_nav` rows.
- In-memory SQLite with both schema files applied; `data/ledger.db` is never
  touched.

## Out of Scope Confirmation

No LLM call, local or hosted. No redaction gate implementation. No holdings
scraping, no per-AMC scrapers, no index-benchmark fetching. No MVO optimizer, no
UI, no broker or execution API.

v0.2 ends at: a cached public market-data layer, five correct literature-derived
metric modules, and a rule engine emitting typed, cited, PII-free findings plus a
trackable health score — all deterministic and unit-tested.

## What v0.3 Inherits

- A `Finding` stream that is self-contained, cited, and already PII-free.
- A citation registry that grounds explanation in named sources.
- One clean insertion point for the redaction gate: between `rules` output and
  any hosted call.
- An open decision, deliberately deferred: local vs. hosted vs. pluggable model
  runtime.
